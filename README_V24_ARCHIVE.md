## Data contract and calculations
`amplop_plans` stores one schema-1 JSONB document per wedding, revision CAS, updated_at, owner-only RPC (service role, fixed search_path, verified actor, lock on workspace), RLS enabled and no direct table grants. API /api/planning POST load/save obtains owner using existing verified bearer flow, validates normalized plan both directions, caps request at 1.2MB, sends no-store. SQL checks size/shape, complete business validation runs in server code; direct service-only RPC trusts server validation. No direct access from staff, guest or anon. No separate WO account or shared collaboration; PIC and vendor contacts are textual coordination fields. No new commercial tier decisions.
- Tasks: title, optional due date, PIC, todo/doing/done, manual checklist. Vendor: name/category/contact, shortlist/contacted/booked/completed, note. Expenses: category, optional vendor link, estimated and nullable final actual. Payments: linked expense, date, positive amount, note; multiple entries for DP/installments/settlement, manual records only, no transfer or Midtrans link. Deleting referenced vendor/expense blocked; remove references/payments deliberately first. Editing/deleting payments allowed; no immutable audit history yet.
- Total estimated = sum estimates; actual known = sum final costs (null excluded); paid = sum payment entries; projected = actual if known, otherwise max(estimate, paid per item); remaining = target − projected (negative is overrun); outstanding = projected − paid. Final cost cannot be lower than recorded payments. Payments are not extra expenses. IDR whole rupiah, no FX/tax model; caps 1 trillion IDR per value, 200 tasks/expenses/rundown, 100 vendors, 300 payments. Technical guardrails, not commercial quotas. Category grouping by labels only, no separate per-category allocation caps. Zero target means budget not yet allocated.
- Rundown: date, start/end in Asia/Jakarta, title, PIC and location. Sorted by date/time; detects potential overlaps, allows parallel activities, no cross-midnight single event (split entries). Dates 2000–2099. Not linked automatically to invitation event schedule. No reminders, calendar sync or WO notifications.
- Export all modules CSV including private contacts and costs; formula protection for strings, fixed-width rows. Summary values in detail column. No guest data or credentials in planning report. Keep private. No import at V24.
