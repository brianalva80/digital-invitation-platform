# V22 release gates — open
All V20 and V21 gates remain open. V22 does not remove inherited limitations.

- Install supported patched Next/React/Supabase versions, lockfile, actual Next build/typecheck and HTTP route tracing (bundle-v14.js required by dynamic guest render). Validate server route headers, proxy/host origin comparison and form encoding; run browser integration with real auth and two distinct workspaces.
- Run SQL fixtures with real PostgreSQL/Supabase; inspect grants and definer privileges. Test parallel import/capacity and RSVP/edit/rotate/delete/payment-block races, malformed input and service-role isolation. Validate revocation of anon/authenticated privileges and tenant access. No database executed in local V22.
- Verify actual sandbox payment and paid publication; test guest link before/after publish, republish, payment blocked, rotation and deletion, stale cached pages. Validate actual POST, refresh, and owner export. Test denied access with invalid token, other workspace token guesses and malformed requests. No production keys or real charges.
- Add platform-level request limits/rate limits for guest endpoints and owner API; prevent abuse, no bearer token URL logging in proxy/APM/analytics, verify TLS/no-referrer/cache behavior. Consider encrypted token storage or hash lookup with owner-only regenerate/reissue, audit and retention policies. Token is bearer capability, not authentication of guest identity. Explicitly communicate forwarded links can be used by others. No third-party analytics on personal links.
- Real device Safari/Android, accessibility, long name/emoji, iframe/outer scroll and audio behavior, external map/download links, responsive guest management, performance (large snapshot JSON fetched twice), native storage and Lighthouse. V14 approved designs immutable; don't refactor them merely to pass staging.
- Owner-approved commercial limits, privacy/consent, guest data deletion and backup/export policy; 500/10/100 are provisional engineering limits. Import retries can duplicate intentionally (append-only); add optional dedupe or idempotency if requested. No automatic token expiry or public guestbook moderation wall. Guest list refresh is manual, no realtime.
- V23 will add check-in separate from RSVP, enforce independent staff authorization/PIN/QR semantics; never treat guest RSVP token as staff authority. Do not activate V23 functionality in V22.
